# SearXNG — private metasearch

A metasearch engine (github.com/searxng/searxng): it sends your query to many search engines at
once and shows the merged results, without the engines seeing who asked or building a profile.
Runs alongside [degoog](degoog.md), so the two approaches can be compared side by side.

## At a glance
| | |
|---|---|
| **URL (domain)** | https://private.williampring.ca |
| **URL (raw)** | http://\<node-ip\>:30880 (NodePort) |
| **Namespace** | `apps` |
| **Deployed by** | Argo CD (GitOps) — ApplicationSet → `kubernetes/apps/apps/searxng/` |
| **Image** | `searxng/searxng`, pinned by **digest** (upstream tags are date + hash, not semver); Renovate opens digest bumps in the weekly `stateless patch updates` group |
| **State** | none — settings come from a ConfigMap; no PVC, no database |
| **Health** | readiness probe on `/healthz` (the same path Gatus checks) |

## Architecture
```
browser
  ├─ https://private.williampring.ca   (Ingress + Traefik + LE cert, via Tailscale)
  └─ http://<node-ip>:30880            (NodePort, raw)
       │
       ▼
  searxng pod  ──► the search engines (outbound, from the node's IP)
     │
     └─ /etc/searxng/settings.yml  ◄── ConfigMap searxng-settings
```

## Files (GitOps — one per resource)
```
kubernetes/apps/apps/searxng/
├── kustomization.yaml   # the four below
├── configmap.yaml       # settings.yml — only the overrides; use_default_settings: true keeps the rest
├── deployment.yaml      # one container, digest-pinned, readiness probe on /healthz
├── service.yaml         # NodePort 30880 → 8080
└── ingress.yaml         # private.williampring.ca → searxng:8080 (cert searxng-tls)
(the Argo Application is generated by kubernetes/bootstrap/apps.yaml — manual sync, CreateNamespace=true)
```

## Settings worth knowing (`configmap.yaml`)
| Setting | Value | Why |
|---|---|---|
| `use_default_settings` | `true` | inherit upstream's defaults; this file only lists what differs |
| `server.limiter` | `false` | the bot limiter needs Valkey; pointless for a personal, Tailscale-only instance |
| `server.image_proxy` | `true` | images in results are fetched by SearXNG, so the engines' image hosts don't see your device |
| `server.secret_key` | ⚠️ still the placeholder | it signs image-proxy URLs — see Known gaps |
| `search.autocomplete` | `duckduckgo` | suggestions as you type |

After editing the ConfigMap: push → Sync → `sudo k3s kubectl rollout restart deploy/searxng -n apps`
(a pod reads `settings.yml` only at startup).

## Known gaps
- **`server.secret_key` is the placeholder string from the template**, in a public repo. Anyone who
  knows it can sign image-proxy URLs, i.e. use the instance as an image proxy. Tailscale-only limits
  that. The fix is listed in [`../platform/secrets.md`](../platform/secrets.md) known debt (a SOPS
  secret passed as `SEARXNG_SECRET`, which overrides the file).

## Using it as the browser's search engine
Settings → Search engine → add `https://private.williampring.ca/search?q=%s`. It only works on
devices with Tailscale running.

## Troubleshooting
| Symptom | Cause / fix |
|---|---|
| Pod `0/1`, "Readiness probe failed" | `/healthz` isn't answering — usually a bad `settings.yml` (YAML error) → `sudo k3s kubectl logs deploy/searxng -n apps` |
| Many engines show errors or CAPTCHAs | the engines rate-limit by IP; it comes and goes. Disable the worst offenders under Preferences → Engines |
| Settings change has no effect | the pod wasn't restarted after the ConfigMap changed (above) |
| `private.williampring.ca` doesn't resolve | the device isn't on Tailscale, or the Cloudflare record is missing ([`../platform/tls.md`](../platform/tls.md)) |
